InlineHookKit

أداة تعليمية لمحاكاة مفهوم Inline Hook باستخدام Python

مشروع عملي في مجال الأمن السيبراني يركز على فهم دورة حياة الـ Hook والـ Patching وإدارة الحالة والاختبارات من خلال بيئة محاكاة آمنة.

الإصدار 0.1.0
نبذة المشكلة الأهداف المعمارية الهيكل المكونات الإعدادات التشغيل دورة الحياة حفظ الحالة الاختبارات الأمان المتطلبات التطوير

1. نبذة عن المشروع

InlineHookKit هو مشروع تعليمي عملي مكتوب بلغة Python، تم تصميمه لدراسة مفهوم Inline Hooking بطريقة آمنة وقابلة للاختبار.

يعتمد المشروع على بيئة محاكاة داخل البرنامج بدلًا من تعديل ذاكرة نظام التشغيل أو ذاكرة عملية خارجية.

تنبيه مهم:

النسخة الحالية من المشروع لا تقوم بتعديل ذاكرة نظام التشغيل الحقيقية، ولا تقوم بحقن كود داخل عمليات خارجية، ولا تنفذ Hook حقيقي على برامج أخرى.

جميع عمليات الذاكرة والـ Patch الموجودة في المشروع هي عمليات محاكاة تعليمية داخل البرنامج نفسه.

2. المشكلة التي يحلها المشروع

دراسة مفهوم Inline Hooking تحتاج إلى فهم عدة مراحل مترابطة، مثل تحديد الهدف، تجهيز البيانات، تطبيق التعديل، التحقق من نجاحه، ثم استعادة الحالة الأصلية.

تنفيذ هذه العمليات مباشرة على ذاكرة نظام حقيقي قد يكون معقدًا وخطيرًا بالنسبة لبيئة تعليمية.

لذلك يقدم المشروع نموذجًا محاكيًا يسمح بدراسة الفكرة الأساسية دون إجراء تعديلات على عمليات خارجية.

الحل: بناء بيئة محاكاة تحتوي على منطقة ذاكرة افتراضية، وبيانات أصلية، وبيانات بديلة، وعمليات Patch، ونظام للتحقق من الحالة وحفظها.

3. أهداف المشروع

  • فهم المفهوم الأساسي للـ Inline Hook.
  • محاكاة عملية تعديل البيانات داخل الذاكرة.
  • تطبيق مفهوم Patch بطريقة منظمة.
  • التحقق من نجاح عملية تطبيق الـ Patch.
  • استعادة البيانات الأصلية عند إزالة الـ Hook.
  • حفظ حالة المحاكاة بين عمليات التشغيل.
  • توفير واجهة سطر أوامر CLI سهلة الاستخدام.
  • تطبيق معالجة منظمة للأخطاء.
  • اختبار المكونات بشكل مستقل.
  • توفير تصميم قابل للتوسعة مستقبلًا.

7. ملف الإعدادات

يستخدم المشروع ملف config.toml لتحديد إعدادات التشغيل والـ Hook. 

[project]
name = "InlineHookKit"
version = "0.1.0"

[runtime]
log_level = "INFO"
dry_run = true
state_file = ".inlinehook/state.json"

[hook]
name = "demo_hook"
target = "target_function"
replacement = "replacement_function"

الإعدادات الرئيسية

الإعداد الوظيفة
log_level تحديد مستوى تسجيل الأحداث.
dry_run تفعيل بيئة المحاكاة الآمنة.
state_file تحديد مكان تخزين الحالة المحاكاة.
name اسم الـ Hook المحاكى.
target الهدف المحاكى.
replacement الاستبدال المحاكى.

8. طريقة التشغيل

يتم تشغيل المشروع من Terminal داخل مجلد المشروع.

عرض المساعدة

python main.py --help

عرض الإصدار

python main.py --version

فحص إعدادات الـ Hook

python main.py inspect

تثبيت الـ Hook المحاكى

python main.py install

عرض الحالة

python main.py status

إزالة الـ Hook المحاكى

python main.py remove

استخدام ملف إعدادات محدد

python main.py --config config.toml status

تحديد مستوى التسجيل

python main.py --log-level INFO status
ملاحظة: يجب تشغيل الأوامر من مجلد المشروع حتى يتم العثور على ملفات الإعدادات والمسارات النسبية بالشكل المتوقع.

9. دورة حياة الـ Hook

NOT_INSTALLED │ │ install ▼ INSTALLED │ │ remove ▼ REMOVED

مرحلة التثبيت

  1. قراءة إعدادات الـ Hook.
  2. إنشاء منطقة ذاكرة محاكاة.
  3. كتابة البيانات الأصلية.
  4. إنشاء Patch محاكى.
  5. تطبيق البيانات البديلة.
  6. التحقق من نجاح عملية التطبيق.
  7. حفظ حالة العملية.

مرحلة الإزالة

  1. التحقق من حالة الـ Hook.
  2. استعادة البيانات الأصلية عند توفر الذاكرة المحاكاة.
  3. التحقق من الاستعادة.
  4. تغيير الحالة إلى REMOVED.
  5. حفظ الحالة الجديدة.

11. حفظ حالة المحاكاة

يستخدم المشروع المكون StateStore لحفظ الحالة المنطقية للمحاكاة في ملف JSON. 

.inlinehook/state.json

مثال على الحالة

{
    "status": "installed",
    "region_address": "0x10000000",
    "patch_size": 8,
    "verified": true
}
مهم: ملف الحالة لا يحفظ ذاكرة حقيقية ولا يجعل Hook حقيقيًا مستمرًا بعد انتهاء البرنامج.

هو فقط يحفظ الحالة المنطقية للمحاكاة حتى تستطيع أوامر CLI المختلفة قراءة حالة العملية السابقة.
