نبذة عن المشروع

InlineHookKit هو مشروع تعليمي عملي مكتوب بلغة Python، يهدف إلى شرح مفهوم Inline Hooking من خلال بيئة محاكاة آمنة داخل البرنامج.

يوفر المشروع دورة كاملة لمحاكاة عملية تثبيت Hook، والتحقق منه، وحفظ حالته، ثم إزالته واستعادة البيانات الأصلية.

تنبيه مهم: النسخة الحالية لا تعدل ذاكرة نظام التشغيل الحقيقية ولا تعدل ذاكرة عمليات خارجية. جميع عمليات الذاكرة والـ Patch تتم داخل بيئة محاكاة تعليمية.

أهداف المشروع

  • فهم مفهوم Inline Hook.
  • محاكاة عملية تعديل البيانات داخل الذاكرة.
  • تطبيق مفهوم Patch والتحقق منه.
  • استعادة البيانات الأصلية عند إزالة الـ Hook.
  • حفظ حالة المحاكاة بين عمليات التشغيل.
  • توفير واجهة سطر أوامر CLI.
  • معالجة الأخطاء بطريقة منظمة.
  • اختبار مكونات المشروع بشكل مستقل.
  • توفير مشروع قابل للتطوير مستقبلًا.

ملف الإعدادات

يستخدم المشروع ملف config.toml لإدارة الإعدادات. 

[project]
name = "InlineHookKit"
version = "0.1.0"

[runtime]
log_level = "INFO"
dry_run = true
state_file = ".inlinehook/state.json"

[hook]
name = "demo_hook"
target = "target_function"
replacement = "replacement_function"

أهم الإعدادات

  • log_level: مستوى تسجيل الأحداث.
  • dry_run: تشغيل المحاكاة الآمنة.
  • state_file: مسار ملف حفظ الحالة.
  • name: اسم الـ Hook.
  • target: الهدف المحاكى.
  • replacement: الاستبدال المحاكى.

طريقة التشغيل

افتح Terminal داخل مجلد المشروع ثم نفذ الأوامر التالية.

عرض المساعدة

python main.py --help

عرض الإصدار

python main.py --version

فحص إعدادات الـ Hook

python main.py inspect

تثبيت الـ Hook المحاكى

python main.py install

عرض الحالة

python main.py status

إزالة الـ Hook

python main.py remove

استخدام ملف إعدادات محدد

python main.py --config config.toml status

تحديد مستوى التسجيل

python main.py --log-level INFO status

دورة حياة الـ Hook

NOT_INSTALLED │ │ install ▼ INSTALLED │ │ remove ▼ REMOVED

أثناء عملية التثبيت يتم إنشاء منطقة ذاكرة محاكاة، ثم كتابة البيانات الأصلية وتطبيق البيانات البديلة. بعد ذلك يتم التحقق من نجاح العملية.

عند الإزالة تتم استعادة البيانات الأصلية والتحقق من نجاح عملية الاستعادة.

حفظ الحالة

يستخدم المشروع StateStore لحفظ حالة المحاكاة في ملف JSON. 

.inlinehook/state.json

مثال:

{
    "status": "installed",
    "region_address": "0x10000000",
    "patch_size": 8,
    "verified": true
}
حفظ الحالة هنا يمثل الحالة المنطقية للمحاكاة فقط، ولا يعني وجود Hook حقيقي دائم داخل ذاكرة نظام التشغيل.

مثال على البيانات المحاكاة

البيانات الأصلية:

ORIGINAL

بعد تطبيق الـ Patch:

HOOK----

يتم التحقق من أن البيانات البديلة تم تطبيقها، ثم عند الإزالة تتم استعادة البيانات الأصلية.

معالجة الأخطاء

يحتوي المشروع على نظام أخطاء منظم للتعامل مع الحالات غير الصحيحة.

  • ملف إعدادات غير موجود.
  • ملف حالة غير صالح.
  • بيانات إعدادات غير صحيحة.
  • محاولة تثبيت Hook مثبت مسبقًا.
  • محاولة إزالة Hook غير مثبت.
  • الوصول إلى منطقة ذاكرة خارج حدودها.
  • الكتابة إلى منطقة ذاكرة غير قابلة للكتابة.
  • بيانات Patch غير صحيحة.

الجانب الأمني

يرتبط المشروع بمجال الأمن السيبراني من خلال دراسة مفهوم Inline Hooking وآليات تعديل التنفيذ.

تساعد المحاكاة على فهم مفاهيم مهمة مثل:

  • تحليل البرمجيات.
  • الهندسة العكسية.
  • تعديل البيانات.
  • Patch Verification.
  • استعادة البيانات الأصلية.
  • دورة حياة الـ Hook.
  • آليات الحماية والكشف.
التطبيق الحالي يستخدم محاكاة آمنة ولا يقوم بتعديل ذاكرة عمليات خارجية.

لماذا تم استخدام المحاكاة؟

  • توفير بيئة آمنة للتجربة.
  • تسهيل الاختبارات الآلية.
  • تقليل الاعتماد على نظام تشغيل محدد.
  • تسهيل فهم الفكرة للطالب.
  • منع التعديل غير المقصود على عمليات النظام.
  • التركيز على التصميم البرمجي ودورة حياة الـ Hook.
